# 31 검증과 운영 계획
상태: 검증·운영 기본안. 통과 수치: 도메인 기준·실험 결과로 결정.

- 관절이 잘 보임·집계 숫자 정확 ≠ 제품 완성
- 확인 대상: 예상 분석 시나리오처럼 상태 → 행동 → 결과 정확 판정, 중요 장면 탐지, 근거 있는 피드백 제공

## 1. 검증 순서

| 단계 | 내용 | 확인 결과 |
|---|---|---|
| 1. 기준과 사례 | 30의 D01~D10 기준과 해당·비해당·판단 불가 사례를 작성. 확정 전에는 임시 운영 정의(24)로 2·3단계 진행 | 분류별 판정 기준, 의견 차이 |
| 2. 가상 데이터 | 상태 구간·행동 사건·결과 판정·관계·집계·출력 검사. 가상 예제 2개에 대한 검사 도구 구현됨(tools/contract_check) | 중복 없음, 분모·판단 불가 처리, 근거 연결. 실제 영상 정확도와 분리 |
| 3. 시나리오 장면 | 예상 분석 시나리오 1~6에 해당하는 실제 짧은 장면에서 선수·포즈·상태·행동·접촉 판정 | 오류가 발생하는 단계, 관측 조건과 실패 사례 |
| 4. 거리와 반복 | 실측 거리와 거리 상태, 같은 상황 묶기, 반복 문제·강점 검증 | 실제 거리 오차, 시나리오 6 같은 반복 집계와 피드백 조건 |
| 5. 전체 영상 | 모든 라운드의 탐지·분할·자원 검사 | 중요 단발 이벤트 누락, 경계 중복, 처리 시간·메모리 |
| 6. 초대 시험 | 초기 사용자(28)가 결과를 이해하고 복기에 활용하는지 확인 | 코칭 유용성, 오해, 정정·삭제·운영 문제 |

- 단계 = 의존 관계·위험 확인 순서, 고정 일정 아님. 거리 실험·모델 비교 등 병행 가능
- 촬영 조건 검증 실험(E1~E6): 26
- 단계별 평가 항목·보고 규칙·정답 자료 작성 원칙·자료 분할: 18

## 2. 운영 기본안

| 항목 | 원칙 |
|---|---|
| 이용자 | 초대받은 시험 참여자. 공개 가입은 기본 비활성화 |
| 접근 | 본인 영상·결과만 조회·정정·삭제. 영상 비공개, 공개 공유 기본 비활성화 |
| 작업 | 업로드 검증 후 큐 등록. 진행 표시, 취소, 일시적 오류 재시도, 중단 복구 |
| 자원 | 순차 디코딩, 구간 저장, 입력 한도 검사. 용량 한도는 실제 장비에서 측정 |
| 원본 | 단기 보관. 근거 클립·재생본·진단 이미지도 영상 파생물로 관리 |
| 결과 | 장기 보관, 사용자 삭제 지원. 원본 만료 시 근거 재생·재계산 불가 표시 |
| 학습·평가 | 별도 이용 목적·권한·동의·보관·삭제 정책 확인 전 원본 자동 복사 금지(32) |
| 진단·보안 | 전송·저장 보호, 서버 권한 검사. 로그에 원본·인증 토큰·민감 내용을 기본 포함하지 않음 |

- 원본·파생 영상 7일, 임시 파일 24시간, 로그 30일: 임시 값, 확정 이용 정책·법정 기간 아님. 임시 값 전체 목록: 27의 10절
- 시험: 사용자별 원본·결과·삭제 상태, 백업 복구 시 삭제 재적용
- 상세: 접근 21, 데이터 수명 15, 작업 12, 자원 13
- 작업 복구 설정: heartbeat 10초(임시), lease 60초(임시), 일시적 오류 재시도 최대 2회(임시). lease = 워커가 해당 작업을 처리할 수 있는 임시 권한
- 실패 시 대응: 23

## 3. 구현 검증 현황

| 대상 | 확인한 내용 | 남은 것 |
|---|---|---|
| 데이터 계약 | 가상 예제 두 개의 집계·문장 회귀 검사, 가져온 사건·판정이 같은 집계값과 문장을 내는지 | 실제 영상의 정답 자료 |
| 시간 동기화 | 일정·가변 프레임률 시험 영상과 실제 영상에서 서버 프레임 표와 브라우저 재생 대조. 브라우저가 일부 프레임을 표시하지 않는 경우 정지 프레임으로 전환 | 스마트폰 촬영 영상 |
| 영상 형식 | 1080p 고정 프레임률, 세로 회전, HEVC mov, 가변 프레임률, 10분 영상, 59분 50초(1.86GiB) 영상 정상. 61분, 4096×2160, 지원하지 않는 코덱·확장자, 손상 파일은 안전한 사유로 거절 | 실제 사용 길이, 동시 업로드 |
| 작업 처리 | 중복 제출, 워커 강제 종료, 취소와 완료의 경합, 소유권 상실, 재시도 한도 | 디스크 부족 주입 |
| 접근 제어 | 다른 계정의 영상·결과·작업·삭제·정정·지정에 접근 불가, 세션 폐기, CSRF, 로그인 시도 제한 | 외부 침투 시험 |
| 삭제 | 파일과 기록이 모두 지워지는지, 정리가 끝나기 전 조회 차단, 원본만 만료 | 백업 |
| 선수 검출·추적 가져오기 | 실제 영상의 파이프라인 출력이 영상의 프레임 시각과 맞는지, 후보 트랙의 진단 값이 파이프라인의 진단 파일과 일치하는지 | 다른 영상(가려짐, 오래 겹치는 장면) |
| 팀 연구 검증(2026-10-14, 영상 6개) | 검출·추적: 기준 01 통과, 02 가림에서 ID 교체 1, 03 관중에서 선수 ID 3개 이상 분할(BLOCKED). 포즈(MediaPipe): 분리 구간 통과·겹침 구간 기각, 품질 행 197개 중 feature 통과 31. 동작 후보 1건(미검증). RTMPose 라이선스 BLOCKED. 상세: 27의 9절, 20A | 정답 자료 없음(precision·recall·ID switch 비율 미산출), 영상 확장, 원거리·관중 선수 연결 |
| 화면 조작 | 실제 브라우저에서 올리기, 가져오기, 선수 지정, 정정, 삭제, 로그인·초대·차단 확인. 발견한 문제(후보 프레임 상자·번호가 보이지 않음, 정정 이력 시각 표기, 결과 제목)는 수정 | 휴대폰 너비, 브라우저별 프레임 표시 |
| 분석 정확도 | 아직 시험하지 않음(분석 단계가 없음) | 모든 항목 |
