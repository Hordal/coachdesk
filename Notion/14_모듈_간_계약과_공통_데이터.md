# 14 모듈 간 계약과 공통 데이터

상태: 사건·집계·피드백 공통 계약 채택, 구현 검증 전

## 1 기본 선택

화면·분석 모듈·저장소 사이 데이터 계약 선통일. 아래 선택: 변경 가능한 프로젝트 기본안, 특정 언어·모델 선택 강제 아님.

| 용도 | 기본안 | 구분·이유 |
|---|---|---|
| 구조 정의 | JSON Schema Draft 2020-12 | 공개 규격. 필수 필드·자료형·범위·조건부 null 검사 |
| API·작업 명세 | UTF-8 JSON | 개발 관행. 영상 자체는 JSON에 넣지 않고 별도 업로드·파일 참조 |
| 시제품 메타데이터 | SQLite, 외래키 활성화, 짧은 트랜잭션 | 단일 호스트 기본안. 여러 서버의 동시 쓰기 필요 시 PostgreSQL 등 재검토. 네트워크 공유 파일로 DB 운영 금지 |
| 프레임별 대량 데이터 | Parquet | 열 단위 분석·압축에 적합. run_id·처리 구간별 파일 저장, 필요한 범위만 읽음 |
| 영상·근거 이미지 | 비공개 파일 저장소 | DB: artifact_id·저장 참조·체크섬·형식·크기만 기록. 외부 응답에 로컬 경로 노출 금지 |
| HTTP 오류 | RFC 9457 Problem Details | 공개 규격. 내부 오류는 공통 code로 변환해 연결 |
| 식별자 | 영구 객체 UUID, 프레임은 artifact_id + 표시 순서 번호 | 팀 규칙. 추적기 임시 번호와 선수 ID 분리 |

Parquet·SQLite 채택: 업계 의무 표준 아님. JSON Schema: 메시지 구조 검증. Parquet 열 자료형·외래 참조·시간·좌표 일관성: 별도 검사.

## 2 모듈 입출력

- 처음: 한 프로그램의 함수·작업 단계로 연결. 모듈별 별도 서버 금지. 대량 배열: 파일 참조 또는 내부 배치로 전달

| 단계 | 필수 입력 | 출력 |
|---|---|---|
| 영상 읽기 | Video, 원본 artifact_id | Frame 목록, 회전·시간 대응·해상도 정보 |
| 검출 | Frame 참조·영상 데이터, 모델 설정 | 프레임마다 한 줄(`detection_frames.jsonl`): timestamp_us, width·height, coordinate_space(analysis_frame_xyxy_px), detections[class_id, class_name, score, bbox_xyxy]. score_type: 모델 설정에 기록 |
| 추적 | 시간순 검출 프레임(신뢰도 임계값 이상 검출을 두 명으로 줄이지 않고 전부 전달), 이전 추적 상태 | 프레임마다 한 줄(`tracking_frames.jsonl`): timestamp_us, tracks[track_id, bbox_xyxy, tracking_score, class_id, class_name, tracking_state]. track_id = 임시 번호, participant_id 아님 |
| 선수 연결 | TrackFrame, 사용자 선수 지정 또는 연결 결과 | TrackAssignment: participant_id, role(USER/OPPONENT), track_ids(여러 개 가능), 적용 구간, 연결 출처. 사용자 선택 전 상태: NOT_RUN |
| 자세 추정 | Frame·Track 참조, 모델 설정 | PoseFrame: timestamp_us, participant_id, track_id(null 허용), keypoints{관절 이름: (x, y, confidence)}, status. landmark_set_id·coordinate_space_id 병기. 팀 연구 포즈(MediaPipe 33점)의 줄 형식: 3절 PoseObservation |
| 지표 계산 | 관측 참조, MetricDefinition, 필요한 보정 정보 | MetricSample: 시각/구간, 값·단위·상태·근거 참조 |
| 상태 판정 | 포즈 시계열·거리 등 지표, 02 상태 정의 | StateInterval·Assessment: 거리/가드/스탠스/밸런스 |
| 행동 판정 | 포즈 시계열·필요 상태·행동 정의 | Event(팀 동작 검출 모델 형식, 분류는 event_label)·Assessment: 타격/방어/이동 + 개별 판정 |
| 결과 판정 | 행동·상태 변화·접촉 근거, 결과 정의 | Assessment + 필요 시 접촉 Event: 타격/방어/거리·위치 결과 |
| 관계 연결 | Event·판정, 관계 정의 | EventRelation·Exchange: 사건 관계·공방 묶음 |
| 반복 집계 | 사건·관계·상황 조건, 집계 정의 | Aggregate: 분자·분모·미판정·제외 수 + 구성원 참조 |
| 결과 구성 | 판정·집계·근거·검토된 피드백 규칙 | Finding: 관찰·집계·원인 가설·교정 방향 구분 주장. 근거 부족 시 해당 주장만 보류 |

- 공통 작업 요청: schema_version, run_id, stage, input_refs, config_ref, interval(전체 처리 시 null)
- 공통 응답: run_id, stage, status, output_refs, warnings, error(null 허용). warnings 항목: module, level(INFO/WARN/ERROR), message, timestamp_us(null 허용). 단계 결과 요약(ModuleOutcome): status(ResultStatus), message, version
- 처리 상태: queued/running/completed/partial/failed/cancelled. 값의 유효 상태와 혼용 금지. 재시도·취소 전이: 12

## 4 자료형과 좌표 규칙

- 시간: 05의 time_us(int64), 구간 [시작, 끝). 필드 이름: Event는 start_timestamp_us·end_timestamp_us(팀 형식), 그 밖의 객체는 start_us·end_us. JSON 전송 시 정수 정밀도 범위 검사. 절대 시각: RFC 3339 문자열
- 검출·추적·포즈 기본 저장 좌표: 분석 프레임(analysis_px, 기본 1280×720). 원점 좌상단, x 오른쪽, y 아래, 단위 px, bbox_xyxy = [x_min, y_min, x_max, y_max]. 표시 좌표(display_px)·부호화 좌표(coded_px): Frame의 FrameTransform으로 복원(03)
- 모델 정규화 좌표: 명시적으로 px 변환. 모델 고유 3차원 좌표: 별도 공간으로 보존, 두 선수 신체 중심 기준 좌표를 바로 빼서 실제 거리로 사용 금지
- 실제 공간 좌표: 공통 기준·보정 근거 있을 때만 연결. 축·원점·단위를 CoordinateSpace에 명시, 변환 불명 시 변환 값 생성 금지
- 관절: 핵심 13개(nose, left·right_shoulder, left·right_elbow, left·right_wrist, left·right_hip, left·right_knee, left·right_ankle)를 이름으로 구분하는 keypoints 사전. 값 (x, y, confidence), z 미사용, 없는 값 null(0 대체 금지). 모델이 더 많은 점(뒤꿈치·발끝 등) 제공 시 landmark_set_id가 정한 이름으로 추가 보존, 공통 규격은 핵심 13개뿐. 모델별 이름 대응표: 별도 관리. 팀 연구 포즈(MediaPipe Pose Landmarker full): 33점, 핵심 13개의 MediaPipe 인덱스 = nose 0, shoulder 11·12, elbow 13·14, wrist 15·16, hip 23·24, knee 25·26, ankle 27·28. 값은 x_norm·y_norm·z_norm·x_px·y_px(분석 프레임)·visibility·presence·off_image·finite. visibility·presence ≠ 관절 정확도, keypoints의 세 번째 값(confidence)에 넣지 않고 별도 필드로 보존. 프레임 밖 좌표는 자르지 않고 off_image로 표시. 눈·귀·입·손·뒤꿈치·발끝은 핵심 13개에 없으나 연구 기록에는 33점 모두 보존
- 저장 자료형 기본: 좌표·점수 float32, 시간 int64, 거리 float64, 횟수·분자·분모 int64, 비율 float64. 결측 null. JSON에 NaN/Infinity 출력 금지
- 시계열: 시간순·구간별 배치 전달. UI: 시간 범위 조회 + 요약값 사용, 전체 프레임 배열 매번 다운로드 금지. 보간 구간을 실제 관측처럼 연결 금지

## 5 유효성·불확실성·오류

| 필드 | 기본 규칙 |
|---|---|
| status | VALID / UNKNOWN / UNSUPPORTED / ERROR. VALID = 산출 조건 충족, 정답 보장 아님. UNKNOWN = 입력 없음·판단 불가(reason_code 병기). UNSUPPORTED = 미지원 구간·조건. ERROR = 실행 오류 |
| provenance | observed / estimated / interpolated / user_provided |
| value·reason_code | 미산출 시 value=null + reason_code 필수. 0 대체 금지 |
| confidence | 모르면 null. 있으면 score_type·producer·calibration_version 병기. 모델 점수를 정답 확률로 표시 금지 |
| uncertainty | 단위 있는 오차 범위·산정 방법 검증된 경우만 기록. 없으면 null, 임의 생성 금지 |
| 주요 사유 | missing_input, identity_unresolved, occluded, missing_scale_reference, invalid_timestamp, unsupported_segment |
| 실행 오류 | code, stage, retryable, 안전한 message, trace_id. 사용자에게 스택·비밀키·로컬 경로 반환 금지 |

- 그라운드 사건의 `status`: 사건 자체의 신뢰, VALID·UNKNOWN만 사용. 사건 확인 + 결과·관계·종료 맥락만 불명 → status VALID, 해당 필드(outcome, relation, finish_context) UNKNOWN(33의 7절). 사건 confidence: 내부 판정·평가용, 화면 정확도로 사용 금지
- 일부 구간 미산출 ≠ 전체 실행 실패. HTTP 요청 성공 후 계산 실패: 실행 상태에 기록. HTTP 요청 자체 실패: RFC 9457 형식 반환

## 6 사건·집계·출력의 확정 규칙

프로젝트 공통 규칙, 격투기 판정 기준·업계 의무 규격 아님. 객체: JSON Schema로 구현할 설계 계약, 현재 실행 가능한 스키마 파일 완성본 아님.

- 사건 형식: 팀 동작 검출 모델 출력(phase1b_v1) 그대로. 분류(action/contact/ground)는 필드가 아니라 event_label에서 파생(서버 domain/events.py, 화면 lib/events.ts)
- 후보 사건(status=CANDIDATE, verified=false): 검출 모델이 낸 검증 전 후보. outcome=UNKNOWN 유지, 타격·접촉·결과로 단정 금지. 집계 포함 여부는 Aggregate의 candidate_refs 정의에서 명시
- participant_id=`candidate:N`: 선수 지정 전 후보(추적 번호 기반), 선수 아님. 가져올 때 UNRESOLVED 선수로 보존, 선수 연결(11)은 track_id 기준. 후보 ID를 USER·OPPONENT로 자동 승격 금지
- 사건·판정 분리. 공격 시도 확인돼도 접촉 결과 unknown 가능. 접촉 사건 없음만으로 빗나감·반격 없음 생성 금지
- Assessment.value와 status: 별개. 관측했으나 애매 → unknown/VALID. 입력 없음 → unknown/UNKNOWN(reason_code=missing_input). 미지원 → unknown/UNSUPPORTED. 실행 오류 → unknown/ERROR. VALID ≠ 정답 보장
- absent: 정의된 관측 조건에서 해당 사실 없음 판정 결과. not_applicable: 질문 비적용. unknown·not_applicable: 사유 기록
- 선수 신원 미확정 → ID 추측 금지. 미확정 사건: 후보로 보존, 특정 선수 집계에서 제외, 제외 사유 기록
- Relation의 시간적 선후 / 반격·인과 관계 구분. 시간 순서만 뜻하는 관계 = followed_by, 반격으로 집계·표현 금지(24). counter_to 등 도메인 관계: 02 기준의 유효한 판정 있을 때만 집계 사용
- Aggregate.scope: 영상·선수·라운드/시간 구간 명시. counting_unit: 공격 시도/접촉 사건 등 세는 대상 명시. 공격별 피격 비율: 고유 공격 ID로 중복 제거, 개별 접촉 수와 별도 계산
- 집계 후보 집합: denominator_refs / unknown_refs / excluded_refs로 겹치지 않게 분할. numerator_refs ⊂ denominator_refs. 제외 사유 보존. 조건부 비율: 후보 집합 자체 명시
- 각 count = 대응하는 고유 ID 수에서 계산. 분모 0 → ratio=null + no_eligible_samples 기록. 미판정·미지원·관측 누락을 성공·실패·0회로 대체 금지
- 집계가 의존한 판정·관계·측정 참조 보존. 상황 분류에 필요한 거리 없음 → 그 상황 집계 보류/미판정, 거리 불필요 집계 유지
- 전체 사건 탐지 완전성 검증 전: '확인된 공격' 집계로 표시. 관측하지 못한 사건: 기존 후보 집합의 unknown 수만으로 설명 불가 → 탐지 누락은 18에서 별도 평가
- 경로 유지: Finding → Aggregate/Assessment/EventRelation/Event/MetricSample → Evidence. 정의·실행 버전이 다른 결과 묵시적 혼합 금지
- 관찰·집계 출력: 구조화된 값 + 템플릿 우선 생성. 숫자·시각을 언어 모델이 새로 생성 금지. 언어 모델 추가 시에도 근거 검사 계약 통과 필수
- 원인 가설·교정 방향: 검토된 규칙 버전 + 충족한 조건·예외 검사 기록 필요. 기준 없음·조건 미판정 → 해당 출력 보류. 전문가: 개발·검증에서 기준 검토, 실사용 건별 검토 필수 아님
- dataset_kind·annotation_source: 가상·수작업·모델 자료별 별도 메타데이터. 02A demo-0.2 예제 두 개(상대 반격 집계, 시나리오 6 반복 집계) = 이 계약의 객체 구분을 따른 가상 예제, 운영 스키마·학습 정답으로 자동 승격 금지

### 분석 분류와 데이터 구조의 대응

- State: StateInterval로 시간 구간별 저장. 앞손·뒷손 Feature: 당시 스탠스/방향에 연결, 이미지 좌우와 동일시 금지
- 행동 전후 상태 변화 분석: 행동 Event가 행동 전/후 기준 시점 StateInterval을 pre_state_refs·post_state_refs로 참조. 기준 시점(기술 판정 단계 중 어느 시점): 02 기준 버전. '공격 후 가드 복귀' 등 행동 후 상태 변화로 정의된 결과 = 이 참조를 입력으로 하는 Assessment
- Action = Event, Output = 해당 행동 대상 Assessment. 실제 접촉 등 시각 있는 사건: 별도 Event와 연결. API 작업 상태 ≠ 격투기 Output
- 피벗 등 이동·방어 겸용 동작: 하나의 행동 ID 유지. 방어 맥락·상대 공격 관계는 같은 ID 참조, 별도 움직임 이중 집계 금지
- 이동 속성(독립): movement_direction(STATIONARY/FORWARD/BACKWARD/LEFT/RIGHT/UNKNOWN) = 자신의 방향 기준, range_change(ENTRY/EXIT/HOLD/UNKNOWN) = 상대 거리 변화. 대각선 이동 = 방향 조합, 피벗 = 행동 사건
- distance_state: OUTSIDE/KICK_RANGE/PUNCH_RANGE/CLOSE_RANGE/CLINCH_RANGE/UNKNOWN. 경계 확정 전·실제 거리 없음 → UNKNOWN
- 프레임 단위 값(forward_component, lateral_component, distance_delta, displacement_x·displacement_y): 단위 병기. 전진 성분 = 사용자→상대 축 기준, 측면 성분 = 그 축을 반시계 90도 회전한 축 기준(해부학적 좌우 아님). 정지·진입 임계값 미설정 → 이동 방향·거리 변화 UNKNOWN. 좌표축·방향 기준 나머지 정의: 02·03
- 상태/행동 목록의 모든 항목을 단일 배타 클래스에 강제 금지. 범주별 label + unknown 판정 지원, 배타성·중첩: 전문가 기준 버전
- 반복 행동·문제·강점: Aggregate + 관련 Finding. 중요 단발 이벤트: 반복 집계 불필요, 해당 Event·상태·결과를 직접 근거로 사용 가능
- 반복 문제: 실제 피격 사건 필수 아님. 검토된 문제 판정 조건 충족 필요. 피격 원인 주장·교정 방향 근거: 각각 별도 검사

## 7 정정과 버전

- 계산 산출물 덮어쓰기 금지. 사용자 의도 설명: 맥락으로 추가, 최초 AI 관측 수정 금지
- 선수 연결·시간 보정 등 계산 입력 변경 → parent_run_id 가진 새 실행 생성. 의존 하위 산출물만 무효화, 영향 없는 결과는 버전 명시 후 재사용
- 파일: 임시 경로에 완성·검사 후 등록. 재실행 중복 구별: 입력 체크섬·모델·설정·구간·정정 버전. 미완성 파일 결과 노출 금지
- schema_version 변경: 읽기 호환성 검사. 필수 필드·의미 변경 시 버전 상승, 과거 결과를 새 의미로 묵시 해석 금지
- 과거 결과 보존 원칙 < 보관·삭제 정책. 삭제 대상 연결: 15

## 8 구현 검증

1. 정상·결측·미지원·오류 샘플 스키마 검사 + 참조 ID·시간 구간·좌표계 확인
2. Parquet 저장·복원에서 null, 관절 순서, 정수 시각 보존 확인
3. 미산출 구간이 그래프에서 0으로 보이지 않고 원본 근거 프레임에 연결되는지 확인
4. 선수 연결 정정 후 새 결과 생성, 이전 결과와 비혼합 확인
5. 실제 영상으로 파일 크기·구간 조회·DB 잠금 대기 측정 → 배치 크기·저장 방식 조정

- 추가 계약 검사: 끊어진 사건 참조, 서로 다른 실행 혼합, 분모 0, 중복 접촉, unknown/absent 혼동, 근거 없는 숫자·교정 문장
- 이 문서에서 미확정: 도메인 관계 유형, 사건 경계, 허용 오차. 실제 측정점·거리 의미·허용 오차: 02·03·18에서 별도 결정. 여기서는 모델·지표 교체 가능한 구조만 결정
