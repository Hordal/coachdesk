# 33 그라운드 사건 분석
상태: MMA 구현안(제안 단계). 구현 범위 = 데이터 구조·가져오기, 분석 방법 미검증. 기준: '판정 기준·제품 결정사항 및 MMA 도입안' 4절.

## 1. 범위

- 스탠딩: 기존 타격 분석(01·24·29) 그대로 사용
- 그라운드: 경기 복기 핵심 사건만 분석, 세부 그래플링 기술 분류 제외
- 종목: 복싱·킥복싱·무에타이 + MMA

| 제품 출력 이벤트 | 뜻 |
|---|---|
| TAKEDOWN | 테이크다운 시도와 결과(SUCCESS·DEFENDED·UNKNOWN). 시도자가 actor, 방어자가 target |
| GROUND_RELATION | 그라운드 상태의 상하 관계(CLEAR_TOP_BOTTOM·NEUTRAL_ENTANGLED·SCRAMBLE_TRANSITION·UNKNOWN) |
| TOP_CONTROL | Clear Top 상태에서 상대의 이동·자세 회복을 제한한 통제 구간과 누적 시간 |
| SUBMISSION_FINISH | 서브미션 상황과 탭·심판 중단이 이어진 종료. 건 선수가 actor, 상대가 target |

제외: 개별 서브미션 기술명, 세부 가드·포지션명, 세부 트랜지션·스크램블 종류, 그래플링 기술 시퀀스, 공식 채점 자동 산출(별도 선택 기능, P06).

## 2. 기본 상태

| 상태 | 정의 |
|---|---|
| STANDING | 두 선수가 주로 발로 체중을 지지하며 스탠딩 공방을 지속 |
| GROUND_TRANSITION | Standing과 Ground 사이가 바뀌는 전환 구간. 테이크다운·넘어짐으로 Ground에 들어가거나 Ground에서 Standing으로 돌아오는 구간 |
| GROUND | 한 명 이상이 몸통·골반을 지면에 두거나, 무릎·손 지지가 일시적이 아니라 지속적인 그래플링 관계를 이룸 |
| UNKNOWN | 가림·화면 이탈·프레임 누락 등으로 위 상태를 신뢰할 수 없음 |

- 무릎·손의 순간 접촉만으로 Ground 전환 금지. 전환 = 연속 구간으로 확인, 최소 유지시간 = 라벨 데이터로 보정(임시: 값 없음, 설정 분리)
- 명확한 시도 없이 한 선수가 스스로 Ground로 내려간 경우: Takedown 미집계

## 3. Ground Relation

| 라벨 | 정의 |
|---|---|
| CLEAR_TOP_BOTTOM | 상하 관계가 명확하고 Top·Bottom 선수를 식별할 수 있음 |
| NEUTRAL_ENTANGLED | 서로 얽혀 있으나 명확한 상하 우위가 없음(레그락 공방 등) |
| SCRAMBLE_TRANSITION | 이미 Ground인 상태에서 상하 관계가 빠르게 바뀌거나 아직 안정되지 않은 구간 |
| UNKNOWN | Ground인 것은 알지만 상하 관계를 판정할 수 없음 |

- 같은 관계가 이어지는 구간 = 이벤트 하나, 관계 변경 시 새 이벤트
- Neutral·Scramble·Unknown: top·bottom 공란 허용

## 4. Top Control

Top Position ≠ Top Control(분리). `NO_CONTROL → CONTROL_CANDIDATE → TOP_CONTROL → CONTROL_END`. CLEAR_TOP_BOTTOM만으로는 Top Control 아님. 후보 조건 = 아래 조합.

- Ground Relation이 CLEAR_TOP_BOTTOM이고 Top·Bottom 선수가 식별됨
- Bottom의 중심 이동·자세 회복이 제한됨
- 두 선수의 상대 위치가 일정 범위에서 유지됨
- Bottom이 즉시 Standing 또는 Neutral로 회복하지 못함
- Bottom이 공격·탈출·역전 움직임을 계속 만들면 추가 통제 근거가 필요

- 확정: 조건이 최소 유지시간 이상 지속 시 TOP_CONTROL
- 종료: 탈출·역전·Neutral/Entangled·Standing 전환·통제 상실
- 시작 시각: 확정은 최소 유지시간 뒤, 기록은 실제 통제 시작 후보 시점으로 소급. `duration_us = end − start`
- 최소 유지시간: 고정 금지, 라벨 데이터로 결정(임시: 값 없음)

## 5. 이벤트 상태 머신

Takedown
- 성공: `STANDING → TAKEDOWN_ATTEMPT → GROUND_TRANSITION → TAKEDOWN_RESOLVED(SUCCESS)`. 시도자의 Top 확정 필요. Top Control: 별도 판정
- 방어: `STANDING → TAKEDOWN_ATTEMPT → TAKEDOWN_RESOLVED(DEFENDED)`. 조건: 방어자가 Standing 유지·회복 또는 시도가 명확히 무효. Neutral·Scramble만으로 자동 방어 처리 금지
- 결과 미확정: 시도 확인, 결과 미확정 → `status=VALID`, `outcome=UNKNOWN`. 시도 자체·구간이 불확실한 경우만 `status=UNKNOWN`
- 연속 체인 동작 = 시도 하나. 명확한 리셋 뒤 시작한 경우만 새 시도. 결과 장기 미확정 시 `takedown_resolve_window`(버전된 설정값) 후 UNKNOWN으로 종료

Submission: `GROUND / CLINCH → SUBMISSION_CANDIDATE → SUBMISSION_FINISH`
- 경기에서 탭·심판 중단 이어짐: `MATCH_WIN`. 스파링에서 탭 뒤 재개: `SPARRING_TAP`
- 이벤트·구간 확실, 종료 맥락만 불명확: `status=VALID`, `finish_context=UNKNOWN`
- 이벤트 자체·구간 불확실한 경우만 `status=UNKNOWN`

내부 상태(`TAKEDOWN_ATTEMPT`, `GROUND_TRANSITION`, `TAKEDOWN_RESOLVED`, `CONTROL_CANDIDATE`, `SUBMISSION_CANDIDATE`)와 제품 출력 이벤트(1절의 4개) 분리. `TAKEDOWN_RESOLVED` 결과값 = `TAKEDOWN.outcome`.

## 6. 판정 기준

| 항목 | 주요 입력 | 확정 조건 | Unknown 조건 |
|---|---|---|---|
| Takedown 성공 | 포즈, bbox, 상대 위치, 중심 높이 변화, Ground Relation | 명확한 시도 → 상대의 Standing 종료 → Ground 진입 → 시도자가 Top으로 확정 | 시도·구간 불명확 → `status=UNKNOWN`. 성공 여부만 불명확 → `VALID`+`outcome=UNKNOWN` |
| Takedown 방어 | 포즈, bbox, 상대 위치, 이벤트 구간 | 시도자가 Top으로 확정되지 않고 방어자가 Standing을 유지·회복하거나 시도가 명확히 무효 | 위와 같음 |
| Ground Relation | 포즈, bbox, 몸통·골반 위치, 선수 겹침, 지면 대비 자세 | 연속 구간에서 관계가 안정적으로 확인 | Ground는 확인되나 관계를 가를 근거 부족 |
| Top Control | Ground Relation, 두 선수 이동량, 상대 위치 변화, 포즈·영상 특징 | 후보 조건이 최소 유지시간 이상 지속 | Top 또는 실제 통제 여부를 구분할 수 없음 |
| Submission Finish | 영상 흐름, 탭 후보, 심판 개입, 스파링 중단·재개 | 서브미션 상황과 종료 맥락이 연속으로 확인 | 이벤트·구간 불명확 → `status=UNKNOWN`. 종료 맥락만 불명확 → `VALID`+`finish_context=UNKNOWN` |

## 7. 출력 계약과 구조 대응

AI 출력: 공통 계약과 같은 JSON/JSONL. 필드 이름 기준 = 아래, 결과 묶음(14)의 사건에는 다음 대응으로 저장.

| 계약 필드 | 결과 묶음의 사건 필드 |
|---|---|
| schema_version, event_id | 같음(schema_version은 묶음 전체에 한 번) |
| event_type | `event_label`(팀 사건 형식 phase1b_v1) |
| start_timestamp_us, end_timestamp_us | 같음(구간은 [start, end), 원본 PTS) |
| initiator_participant_id, defender_participant_id | `participant_id`, `target_participant_id`(TAKEDOWN) |
| actor_participant_id, target_participant_id | `participant_id`, `target_participant_id`(SUBMISSION_FINISH. 건 선수가 actor, 상대가 target. 이 두 필드 이름은 계약에 명시가 없어 임시로 정함) |
| top_participant_id, bottom_participant_id | 같음(GROUND_RELATION·TOP_CONTROL) |
| outcome, relation, finish_context | 같은 이름 |
| status(VALID·UNKNOWN) | `status` |
| confidence | `confidence`(null 허용). 내부 판정·평가용, 사용자 화면의 '정확도' 아님 |
| evidence(구간, participant_tracks) | Evidence 항목 1개 생성 후 `evidence_ref`로 연결. 구간·관련 선수 보존 |
| duration_us(TOP_CONTROL) | 미저장, end − start로 계산. 입력값이 다르면 거절 |

- 모든 이벤트: 시작·끝 시각 + 근거 필수
- participant_id·track_id 분리

Unknown 4종
- `status=VALID`: 이벤트 존재·구간 신뢰 가능
- `status=UNKNOWN`: 이벤트 존재·구간 자체 확정 불가
- `status=VALID` + `outcome=UNKNOWN`(또는 `finish_context=UNKNOWN`): 이벤트 확인, 결과·종료 맥락만 불명확
- `relation=UNKNOWN`: Ground 확인, 상하 관계만 판정 불가

14의 Assessment 상태(VALID·UNKNOWN·UNSUPPORTED·ERROR)와 비중복: 사건의 `status` = VALID·UNKNOWN만 사용.

## 8. 라벨링 기준

| 라벨 | 시작 | 종료 |
|---|---|---|
| Takedown | 상대의 균형·지지 기반을 무너뜨리려는 명확한 시도가 시작된 시점 | SUCCESS·DEFENDED·UNKNOWN 중 하나로 확정된 시점 |
| Ground Relation | 관계가 연속으로 확인되기 시작한 시점 | 다른 관계·Standing·Unknown으로 바뀌는 시점 |
| Top Control | 최소 유지시간을 채운 후보의 실제 시작 시점 | 통제 상실·역전·Neutral/Entangled·Standing 전환 시점 |
| Submission Finish | 종료 사건이 확인되기 시작한 시점 | 탭·심판 중단 또는 스파링 재개로 종료 맥락이 확정된 시점 |
| 관찰 불가 구간 | 가림·화면 이탈·프레임 누락으로 선수·포즈·상황을 관찰할 수 없게 된 시점 | 다시 신뢰할 근거가 확보된 시점 |

Takedown 성공·방어: 별도 이벤트 없이 같은 Takedown의 `outcome`으로 기록.

- 시간: 원본 PTS(timestamp_us)
- 애매한 장면: `status=UNKNOWN`·`outcome=UNKNOWN`·`relation=UNKNOWN`·관찰 불가 구간 중 목적에 맞는 것으로 구분, 추측 라벨 금지
- 같은 영상 안에서도 판정 가능 구간·Unknown 구간 분리
- 최소 유지시간·이벤트 병합 간격: 라벨 분포 확인 후 결정
- Train·Validation·Test: 같은 영상·같은 선수 혼합 금지
- 일부 구간: 2명 이상 독립 라벨링 → 기준 불일치 사례 정리

## 9. 구현·검증 원칙

- 방법 후보: 24의 6절. 아래 = 제안서 원칙
- 첫 기준선: 포즈 + bbox + 상대 위치 + 시간 특징. 그라운드에서 2D 포즈가 가림·겹침으로 불안정 시 영상 기반 시계열 분류기 결합. 포즈만으로 최종 방식 고정 금지
- 모델이 판단하지 못한 장면: 실패 아닌 Unknown으로 보존
- 최소 유지시간·평활화·이벤트 병합 간격: 코드 고정 금지, 버전된 설정값 관리
- 평가: Precision·Recall·F1, 이벤트 시작·끝 오차, Unknown 비율, 중요 사건 누락률(18)
- 제품 활성화 전 이벤트별 검증 기준 설정, 기준 미달 기능 = 실험 기능 또는 비활성
- 사용자 정정 가능 대상: Takedown outcome, Submission Finish, Ground Relation, 관찰 불가 구간. 서버 기존 정정 구조(11)와 연결
