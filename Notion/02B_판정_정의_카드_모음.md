## 2. 관계 기반 알고리즘

도메인 경계값 없이 구조만으로 짤 수 있는 판정 절차. 입력은 선수별 사건(공격 · 방어 동작 · 접촉)과 상태 구간. 매개변수는 기호로 두고, 산출 가능한 값은 3.1절 참조(나머지 `미정`).

표기
- Atk(a): 공격 사건(14의 Event, 팀 동작 검출 모델 형식). 시작 s = start_timestamp_us, 종료 e = end_timestamp_us, 최대 동작 시점 p = phase_marks 또는 근거 측정, 행위 선수 actor = participant_id, 대상 선수 target = target_participant_id. 후보 사건(status=CANDIDATE)은 후보로만 취급
- Def(d): 방어 동작 사건(블록 · 패리 · 상체 회피 · 이동 회피). 시작·종료, 행위 선수
- Con(a): 공격 a의 접촉 판정(있음·없음·판단 불가, 부위 head·body·leg·guard·불명확)
- 시간 매개변수: δ_link(공격과 방어 동작의 연결 허용 간격), δ_counter(방어 후 반격 허용 간격), ε_before·ε_after(전후 상태 기준 시점 간격), τ_d(거리 변화 허용 오차), k_min(반복 최소 근거)
- 판단 불가 전파: 입력 중 하나가 UNKNOWN이면 출력도 UNKNOWN(사유 = 입력 사유 포함). 뒤 사건의 유효 판정은 앞 사건이 불명확해도 유지(29의 5절)

### 2.1 후보 사건 정책

구현됨: `backend/app/domain/policy.py`

| 사건 상태 | 처리 |
|---|---|
| 확인(`status=VALID`, `verified`가 false 아님) | 집계·판정 대상 |
| 후보(`CANDIDATE`, `verified=false`, 상태 없음) | 집계에서 제외. 가져오기 메모에 제외 건수 기록 |
| 불명(`UNKNOWN`) | 집계에서 제외. 메모에 건수 기록 |

- R1: 후보 공격 → 판단 불가(`candidate_event`). 확인되지 않은 방어 후보만 있으면 판단 불가(`defense_candidate_unconfirmed`), '없음' 아님
- R3: 후보 반격은 연결하지 않음
- R8: 후보 접촉은 장면 후보에서 제외
- 후보를 확인 사건으로 자동 승격하지 않음

### 2.2 `candidate:N` 역할 제안

구현됨: `backend/app/domain/candidates.py`, `GET /runs/{id}/candidate-roles`
- 사용자가 고른 트랙 지정(USER/OPPONENT)과 후보의 `track_id`가 완전히 겹칠 때만 제안
- 제안 불가 사유: `no_designation`, `no_track`, `conflict`, `track_not_designated`, `partial_match`
- 제안은 저장·적용하지 않음. 반영은 본인 지정 정정으로만
- 번호 크기·입력 순서·화면 위치로 정하지 않음

### R1. 방어 연결 (방어 상태·방어 사건)

구현됨: `backend/app/domain/relations.py`(`link_defenses`). 관측 구간이 연결 창을 덮을 때만 '없음', 아니면 판단 불가. 방어 라벨 집합은 임시(`BLOCK`·`PARRY`·`SLIP`·`DUCK`·`LEAN_BACK`·`STEP_BACK`·`EVADE`), 팀 라벨 확정 시 교체

방어 = 한 선수의 공격에 대해 상대 선수가 방어 동작으로 분류되는 동작을 취한 관계.

```
for each Atk a with actor A, target B:
    candidates = { d in Def : d.actor == B
                   and interval(d) overlaps [a.s - δ_link, a.e + δ_link] }
    if a or any d in 관측 불가/UNKNOWN: link = UNKNOWN
    elif candidates 비어 있음:           link = NONE   # '방어 행동 없음'(관측 근거로 판정)
    else: link = argmax_overlap(candidates, a.p 근처 우선); 나머지 d는 보조로 기록
output: DefenseLink(atk=a, def=d or NONE/UNKNOWN, defender=B)
```
- '없음'(관측했고 방어 동작이 없었음) ≠ UNKNOWN(관측 불가)
- 한 공격에 방어 동작 여러 개 → 가장 많이 겹치는 1개를 주 연결, 나머지는 보조 연결로 기록(집계 단위: D06 결정)
- 연결 시간 간격 δ_link: 고정 초 수 전제 금지, 행동 경계 기준으로 정의(미정)

### R2. 타격 결과 결정 (2단계, D07)

입력: Con(a), R1의 DefenseLink. 접촉 판정은 1단계 결과를 그대로 사용.

| 접촉 | 접촉 부위 | 방어 연결 | 결과 |
|---|---|---|---|
| 있음 | head · body · leg | NONE | 명중 |
| 있음 | guard | 방어 동작 있음(블록·패리) | 방어됨 |
| 있음 | head · body · leg | 방어 동작 있음 | 판정 보류 후보(부분 방어, D07 결정) |
| 없음 | — | 상체·이동 회피 있음 | 회피됨 |
| 없음 | — | NONE | 빗나감 |
| 판단 불가 또는 방어 연결 UNKNOWN | — | — | 판단 불가(사유 전파) |
| 있음 | 불명확 | — | 접촉 있음 기록, 결과 판단 불가 |

- 1단계 결과만으로 방어 성공·회피 주장 금지 → 이 표는 2단계 이후에 사용

### R3. 반격·교환 연결

구현됨: `relations.py`(`link_counters`). 방어 연결된 공격만 입력. 팀 모델에 방어 사건이 없는 동안은 결과 없음

```
for each defense link L(a1 → d) with defender B:
    for each Atk a2 with actor B:
        if a2.s >= d.s and a2.s <= d.e + δ_counter and a2.s > a1.s:
            if a2.s < a1.p:  type = EXCHANGE      # 동시 공격(서로 때림), 반격 아님
            else:            type = COUNTER(a1, a2)
```
- 동시 공격·독립적인 다음 공격 구별: a2가 a1 최대 동작 이전에 시작하면 교환, 방어·회피 동작 이후에 시작하고 δ_counter 안이면 반격
- 반격 판정 기준(D06) 확정 전에는 1단계의 followed_by(시간적 후속 공격)만 기록

### R4. 거리·위치 결과

구현됨: `relations.py`(`judge_range`). 거리 표본(박스 높이 단위)을 입력으로 받음. 표본이 기준 시점 근처에 없으면 판단 불가. 거리 상태 산출 미구현

```
d_before = 거리(t_a.s - ε_before),  d_after = 거리(t_a.e + ε_after)    # D01 M-01 또는 M-02
Δ = d_after - d_before
if d_before 또는 d_after UNKNOWN: UNKNOWN
elif |Δ| <= τ_d:  거리 유지
elif Δ < -τ_d:    거리 진입(진입 성공/불리한 진입은 상대 반응·피격과 조합, D07)
elif Δ >  τ_d:    거리 확보(공격 선수가 벌렸으면) / 거리 회복(밀린 선수가 되찾았으면)
```
- 행동 선수가 누구인지(전진·후퇴의 주체)는 movement_direction·range_change 속성과 함께 판정
- ε_before·ε_after: 행동 전·후 기준 시점(D05) 확정 전에는 미정

### R5. 공격 후 가드 복귀

구현됨: `backend/app/domain/analysis.py`(`judge_guard_return`, `derive_guard_return`). 가져오기 입력의 `derive: ["rear_guard_return"]`로 사건·상태 구간에서 판정·집계·주장을 서버가 생성. 02A 시나리오 6 예제(집계 4/6, 문장)를 같은 값으로 재현(`tests/test_analysis.py`). 복귀를 못 봤어도 기준보다 오래 비복귀를 관측하면 지연(하한), 관측이 기준에 못 미치면 판단 불가

```
t_ret = min{ t >= a.e : guard_state(actor, t) in 기준 자세 범위 }     # 기준 자세: D02
delay = t_ret - a.e
if t_ret 없음 and 다음 행동 시작 전까지 관측 가능: 복귀 지연 = 복귀 없음   # 0·실패로 대체 금지
if 관측 불가 구간이 포함: UNKNOWN
```
- 복귀 지연의 문제 판정 임계값: 미정(분포 확인 후 결정)

### R6. 공격 후 밸런스 회복

구현됨: `relations.py`(`judge_balance_recovery`), R5와 같은 `judge_recovery` 공유. 밸런스 상태 라벨(`stable` 등) 산출은 미구현

R5와 같은 구조로, 시작 = 행동 종료, 끝 = 밸런스 관련 주요 Feature가 기준값 범위로 복귀한 첫 프레임. 기준값 범위: 미정(D04). 복귀하지 못하면 '회복 없음', 관측 불가면 UNKNOWN.

### R7. 반복 집계

구현됨: `analysis.py`(`derive_post_action`)로 일반화. 공격 뒤 상태 판정 함수를 받아 선수·기술별 집계와 주장 정의를 생성. 적용: 가드 복귀(`derive: rear_guard_return`), 밸런스 회복(`derive: balance_recovery`). 반복 문제 판정·교정은 규칙 미검증으로 보류 고정

```
group key = (거리 상태 at 행동 전, 행동 종류, [스탠스])      # '같은 상황' 조건: D08
N_all      = 해당 key 공격 시도 수(확인된 전체)
N_judged   = 결과 판정 가능 수
N_event    = 문제 결과(예: 복귀 지연) 발생 수
N_unknown  = 판단 불가·제외 수
출력: "N_all 중 N_judged 판정 가능, N_event 발생, N_unknown 판단 불가"
if N_judged == 0: 비율 없음
if N_event < k_min: 반복이라 표현하지 않고 횟수만 서술
```
