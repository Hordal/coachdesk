# 22 개발과 배포
상태: 변경 가능한 기술 기본안, 외부 배포 실행은 별도

## 시제품 기술 조합
| 계층 | 기본안 |
|---|---|
| 분석·백엔드 | Python, FastAPI. 영상 분석 생태계·API를 한 언어로 연결 |
| 화면 | TypeScript·React·Vite, 웹 브라우저 기반 |
| 영상 | FFmpeg·FFprobe, 05 규칙 |
| 저장 | SQLite 메타데이터·Parquet 시계열·비공개 파일, 14 규칙 |
| 실행 | API + 단일 분석 워커, 별도 프로세스 |

- 업계 의무 규격 아님, 프로젝트 초안
- Python 3.11 이상. Python·Node·모델 환경: 호환성 확인 후 버전 고정. GPU 환경 확인 전 CUDA 버전 가정 금지
- 디렉터리 구조·API·화면·구현 순서: 27
- 현재: 서버(FastAPI) + 첫 클라이언트 웹 화면(React·Vite) 구현(데스크톱·모바일 확장: 27의 7절). 저장: SQLite + 비공개 파일(Parquet 미사용)
- 의존성 고정: `backend/requirements.lock.txt`, `frontend/package-lock.json`
- 남은 일: 배포 환경, 백업·복구 시험

## 개발 운영
- Git 저장소: PR 검토, 의존성 lock, 샘플 설정, 비밀값 없는 .env.example
- Git 제외: 원본 영상, 키, 모델 대용량 파일
- CI: 계약 검사, 단위 검사, 샘플 영상 통합 검사. GPU 검사: 실제 장비 별도 작업
- 컨테이너: 배포 재현 수단, GPU·OS 호환성 선시험. Docker Compose 단일 호스트 구성 가능, 초기 Kubernetes 도입 금지
- 호스팅 위치·인증 제공자·장비: 자원 확보 후 선택

## 배포·복구
- 공개 조건: 초대 참여자 운영, TLS·접근 제어·보관 정책 검증 후
- DB 마이그레이션·백업 복구 시험, 이전 앱 버전 ↔ DB 호환 확인
- 스키마 변경 후 앱 파일만 되돌린 것 = 복구 아님

검증: 새 팀원 장비에서 문서대로 실행, 샘플 분석 끝까지 수행, 배포 실패·이전 버전 복구 시험.
근거: Docker build 지침 — https://docs.docker.com/build/building/best-practices/. 프레임워크 선택: 프로젝트 기본안.

도구 문서: FastAPI — https://fastapi.tiangolo.com/, Vite — https://vite.dev/guide/, React TypeScript — https://react.dev/learn/typescript.
