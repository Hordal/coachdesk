# 05 시간과 동기화

상태: 잠정 설계, 구현 검증 전

## 목적

원본 영상·분석 프레임·그래프·근거 클립이 같은 시점을 가리키도록 맞춤.

## 잠정 설계

| 항목 | 규칙 |
|---|---|
| 공통 기준 | 원본 영상 재생 시작 = 0인 상대 시각 |
| 내부 표현 | 정수 마이크로초 time_us. 저장 정밀도이며 분석 정확도 아님 |
| 구간 | [start_us, end_us), 시작 포함·끝 제외 |
| 프레임 | 프레임 번호 + 원본 표시 시각 병기. 프레임 번호 ÷ 명목 fps 단독 의존 금지 |
| 원본 연결 | 디코더의 원래 표시 시각·time base·재생 시작 오프셋 보존 → 공통 시각으로 변환 |
| 변환·샘플링 | 자르기·프레임 추출·재인코딩 후에도 원본 시각 대응 유지 |
| 라운드 | 원본 시간과 별개로 시작·끝 기록 |
| 절대 시각 | 업로드·분석 생성 시각: RFC 3339, 별도 기록 |

## 기본 처리 규격

공식 문서·일반 구현 방식 참고 프로젝트 기본안. FFmpeg 채택·허용 형식 목록은 업계 의무 표준 아님. 구현 검증 후 조정.

| 항목 | 기본안 |
|---|---|
| 입력 형식 | MP4·MOV 컨테이너의 H.264·HEVC 우선 허용. 확장자 외 실제 스트림·디코딩 가능 여부 검사. 나머지: 미지원 안내 |
| 처리 도구 | FFprobe: 스트림·프레임 정보 조회 / FFmpeg: 디코딩·변환·프레임 추출. Python 내 직접 디코딩 필요 시 PyAV 검토(필수 의존성 아님) |
| 가변 프레임률 | VFR 허용. 프레임별 표시 시각·time base 사용, 명목 fps로 시각 재구성 금지, 분석용 일괄 CFR 변환 금지 |
| 브라우저 재생본 | 웹 화면 채택 시 MP4/H.264 재생본 생성 가능하게 설계. 원본 보존, 재생본·분석 프레임의 원본 시간 대응 유지. 정밀 분석은 재생본 품질에 비의존 |
| 회전 | 회전 메타데이터로 올바른 방향 디코딩·표시, 좌표도 동일 기준. 원본→분석 좌표 변환 기록, 회전 중복 적용 방지 |
| 정상 편집 영상 | 올바르게 재생되는 자르기·이어붙이기 영상 수용. 업로드 파일의 재생 시각 = 원본 기준. 확인된 컷 경계 너머 추적·보간 금지. 원래 경기의 끊김 없는 시간으로 간주 금지 |
| 속도 변경·리플레이 | 재생 시각 ↔ 실제 동작 시간 대응 미확인 시 해당 구간 실제 속도·빈도 분석 보류. 자동 탐지의 모든 편집 발견 보장 없음 |
| 비정상 시간 정보 | 디코딩 순서 ≠ 표시 순서: 정상. 디코딩 후 표시 시각 누락·역행·불연속 검사. 근거 없는 균일 fps 복구 금지. 신뢰 가능한 시간 대응 불가 → 시간 기반 분석 중지, 재업로드 안내 |
| 일반 탐색 | 웹 플레이어: currentTime 이동 후 seeked 뒤 실제 표시 확인. 정밀 이동에 fastSeek(정확도 양보) 사용 금지 |
| 프레임 확인 | 지원 브라우저: requestVideoFrameCallback의 mediaTime으로 표시 시각 확인. 프레임 단위 탐색 보장 아님 |
| 정확한 근거 확인 | 디코더가 원본 표시 순서·시각으로 식별한 프레임을 정지 이미지로 제공. 프레임 ID·시각·좌표 결합, 동일 시각 프레임도 ID로 구별. 브라우저 탐색만으로 정확 프레임 보장 안 함 |
| 시간 일치 기준 | 일반 근거 탐색 잠정 허용 오차: 목표 시점 부근 원본 1프레임 표시시간 이내. VFR: 고정 1/fps 대신 인접 표시 시각. 미달·확인 불가 → 정지 프레임 확인으로 전환. 업계 표준 수치 아님, 프로젝트 기본 목표 |

## 구현 시 검증할 사항

- 실제 스마트폰 MP4·MOV / H.264·HEVC / VFR 영상의 디코딩·회전·시간 대응
- 선택한 FFmpeg 배포본의 코덱 지원·라이선스, 실행 환경 호환성
- 브라우저별 탐색 오차·프레임 콜백 지원. 미지원 환경: 정확 프레임 이미지 사용
- 편집 경계·시간 이상 감지 실패 사례. 자동 탐지 범위: 시험 후 명시

## 구현에서 확인한 사항(2026-10-05)

개발용 시험 영상(고정 30fps, 일부 프레임 제거한 VFR)으로 서버 프레임 표 ↔ 브라우저 재생 비교.

- ffprobe: 패킷 시각을 디코딩 순서로 출력(B-프레임) → 표시 순서 정렬 필요. 프레임 번호 = 정렬한 표시 순서
- 고정 프레임률도 반올림 때문에 프레임 간격이 두 값(33333·33334µs). 시각 = 정수 PTS × time_base 반올림(0.5는 올림) 마이크로초
- VFR 판정: 평균 프레임률과 보고된 프레임률의 상대 오차 0.1% 초과 시(선수 검출·추적 파이프라인과 동일 방식). 두 프레임률 불명일 때만 프레임 간격 차이가 반올림 오차(2µs) 초과 여부로 판단. 시각 계산은 판정과 무관하게 항상 프레임별 PTS
- Chrome: VFR 영상에서 ffprobe·ffmpeg 디코더가 내보내는 프레임 일부 미표시(앞 프레임 기록 길이가 다음 프레임 시각을 덮는 경우). '브라우저 탐색만으로 정확 프레임 보장 안 함' 규칙 확인. 이동 후 표시 확인, 미표시 시 정지 프레임 전환 필요(27의 4.3)
- 시각 그대로 탐색 시 반올림 때문에 이전 프레임 표시 가능 → 프레임 사이 중간 지점으로 탐색. 정지 프레임 추출도 동일
- 미확인: 실제 스마트폰 영상(MOV·HEVC, 회전 메타데이터), 다른 브라우저, FFmpeg 배포본 라이선스

## 근거 문서

- FFmpeg 공식 문서 — https://ffmpeg.org/ffmpeg.html: 디코딩·변환·타임스탬프·탐색·회전 처리
- FFprobe 공식 문서 — https://ffmpeg.org/ffprobe.html: 스트림·프레임 정보 조회
- requestVideoFrameCallback — https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback: 표시 프레임 mediaTime 확인
- fastSeek — https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/fastSeek: 정밀도 양보 빠른 탐색

## 확인 방법

1. 일정·가변 프레임률 영상: 지정 분석 시각 ↔ 재생 장면 대조
2. 영상 자르기·분석용 프레임 축소 후에도 근거가 원본의 같은 동작에 연결되는지 확인
3. 인접 구간 경계에서 동일 사건 중복 집계·누락 여부 확인
