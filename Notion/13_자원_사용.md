# 13 자원 사용
상태: 단일 호스트 자원 기본안, 실제 용량은 실측 필요

## 기본 설정
- 분석 워커 1개, 동시 분석 1건(임시)
- 영상 순차 디코딩, 전체 프레임 메모리 적재 금지
- 자세·거리 데이터: 구간별 저장. 원본·대량 프레임 복제 최소화
- 외부 요청: 큐 대기

## 입장 검사
- 검사 항목: 업로드 크기, 재생시간, 픽셀 수, 예상 디코딩량, 가용 디스크
- 최대값: 짧은·중간·최대 목표 영상으로 메모리·처리시간 측정 후 설정 파일에 기록
- 자원 부족: 무한 대기·반복 실패 대신 사유 안내

## 예산 기록
- 파일 크기만으로 처리량 추정 금지
- 기록 항목: 해상도×프레임수, 모델 배치, GPU 메모리 최고치, 임시 파일 최대 크기, 단계별 시간
- 여유 용량 남긴 한도를 운영 설정으로 적용, 예상 밖 입력 거부

## 검증
- 큰 해상도·장시간·손상 파일·디스크 부족에서 프로세스·저장소 복구 확인
- 동시성 확대: 실측 후
- 현재 장비·예산 = 최종 제품 성능의 전제 아님, 확보 계획의 입력

## 구현 반영
- 입장 검사 2단계
  - 업로드 전: 확장자(mp4·mov), 크기, 남은 디스크 공간
  - 파일 수신 후: 실제 스트림 읽기 → 컨테이너, 코덱(H.264·HEVC), 길이, 해상도
  - 거절: 사유 코드와 함께 안내
- 한도(환경 변수로 변경 가능): 파일 4 GiB(임시), 길이 1시간(임시), 해상도 3840×2160(임시), 필요 여유 공간 = 파일 크기의 3배(임시)
- 영상 규격: 720p·30fps 이상 기본 지원, 1080p·60fps 권장. 최대 길이: 서버 성능 실측 후 결정
- 규격 미만 영상: 거절 없이 영상 준비 결과에 기본 지원·권장 대비 충족 여부 표시
- 영상 준비 실측: 1080p 24fps 59분 50초(1.86GiB) 약 5분 30초, 디스크 = 원본의 약 1.6배(원본 + 재생용 사본)(27의 9절)
- 남은 일: 분석(검출·추적·포즈) 시간 측정 후 이 문서에 기록(제품 모델 확정 후)
- 길이 1시간: 스파링이 30분을 넘을 수 있다는 판단의 임시 상한. 분석 단계 처리 시간 측정 후 결정

실측(RTX 4070 SUPER, Windows)
- 영상 준비(전체 읽기 검사, H.264 재생용 사본, 프레임 표 대조): 1080p 17초 영상 약 2초, 10분 영상(324MB, 14,652프레임) 약 59초
- 선수 검출·추적(RT-DETR R18, ByteTrack): 1080p 17초(407프레임)를 분석 프레임으로 변환해 처리 — 검출 66.6초(초당 6.1프레임), 추적 갱신 0.07초
- 검출 모델 추론만: 프레임당 33.6ms(초당 29.8프레임). 프레임당 163ms 중 전처리 126ms가 최대
- 전체 실행 약 4분(2026-10-06 실행 기록): 검출·추적 오버레이 영상 생성·진단 파일 작성 포함
- 분석 전체 길이별 처리 시간: 미측정
