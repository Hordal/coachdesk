# 12 처리 작업 관리
상태: 단일 호스트 시제품 기본안

## 기본 구조
- 웹/API 요청과 장시간 분석 워커 분리
- 초기: SQLite 작업 테이블 + 별도 워커 프로세스로 충분한지 검증
- 메모리에만 작업 보관 금지
- 다중 서버 필요 시 큐·DB 재검토

| 사건 | 처리 |
|---|---|
| 업로드 완료 | 임시 파일 검증 → 원본 등록 → 작업 생성 |
| 작업 시작 | 짧은 DB 트랜잭션으로 소유권·lease 확보 |
| 정상 처리 | stage·진행량·heartbeat·체크포인트 기록 |
| 종료 | completed/partial/failed/cancelled 기록 |
| 프로세스 중단 | 만료 lease 확인, 마지막 완성 체크포인트부터 복구 |
| 중복 요청 | 사용자 범위 idempotency_key로 같은 요청 반환 |
| 취소 | 취소 플래그 확인, 하위 프로세스 종료, 미완성 출력 미등록 |

- heartbeat 10초(임시), lease 60초(임시), 일시적 오류 최대 2회 재시도(임시)
- 긴 디코딩 중에도 heartbeat 별도 유지
- 잘못된 입력·미지원·권한 오류: 자동 재시도 금지
- lease 갱신·취소 시 소유권 토큰 확인 → 이전 워커의 늦은 쓰기 차단

## 완료 기록
- 파일: 임시 생성 → 검증 → 동일 저장소 내 원자적 이름 변경 → DB 등록
- 중단으로 생긴 고아 파일: 정리
- DB·파일 단일 트랜잭션 가정 금지

## 검증
- 주입 시험: 중복 제출, 워커 강제 종료, 취소/완료 경합, 디스크 부족
- 진행률: 처리 구간 기준. 근거 없는 완료 예정 시간 표시 금지

## 구현 반영
- 구조: SQLite 작업 테이블 + 별도 워커 프로세스
- 소유권 토큰 + lease 60초, 워커가 10초마다 heartbeat로 연장
- lease 만료 → 다른 워커가 마지막 완료 단계부터 이어서 처리, 이전 워커의 늦은 쓰기 거부
- 시도: 최대 3회(재시도 2회). 영상 손상 등 영구 오류: 재시도 안 함
- 취소: 대기 중이면 즉시, 처리 중이면 하위 프로세스 중지 + 미완성 출력 삭제
- 영상 준비 작업 단계: 전체 읽기 검사 → 재생용 사본 생성 → 프레임 시각 확인 → 결과 등록. 분석 단계: 미지원 표시
- 진행 표시: 단계 가중치 비율만, 완료 예정 시간 없음
- 오류 내용: 안전한 제목, 영상 시각, 확인 번호만(내부 경로·FFmpeg 출력 제외)
- 자동 시험 확인: 중복 제출, 워커 강제 종료, 취소·완료 경합, 소유권 상실, heartbeat 유지·미유지
- 디스크 부족 주입: 입장 검사까지만 시험
