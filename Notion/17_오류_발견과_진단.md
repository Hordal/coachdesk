# 17 오류 발견과 진단
상태: 진단 기본안

## 최소 진단 도구
- 원본 프레임 위 선택적 오버레이: 검출 bbox, track_id, participant_id, 관절, 보정 유효 상태
- 함께 확인: 원본·파생 관측, 시간별 결측률, ID 변경, 단계 처리시간
- 대화형 운영자 열람: 21의 권한 준수

## 로그
- JSON 구조화 로그: timestamp, level, run_id, stage, trace_id, error_code, duration, 처리량
- 기본 로그 제외: 원본 프레임, 전체 분석 내용, 인증 토큰, 서명 URL, 사용자 실명
- 단계별 trace/span: OpenTelemetry 개념 참고, 별도 수집 서버는 초기 필수 아님

## 오류 분류
입력 손상 / 시간 대응 / 검출 / 선수 연결 / 자세 / 보정 / 지표 / 사건 탐지·분류 / 접촉 판정 / 반격 관계 / 사건 중복·집계 / 근거 연결 / 원인·교정 규칙 적용 / 문장 생성 / 저장 / 화면 동기화 / 자원 부족. 사용자 표시: 안전한 메시지 + 문의용 trace_id만.

## 검증
- 각 단계에 고의 오류 주입 → 최초 원인이 로그에서 구별되는지 확인
- 로그 민감정보 검사
- 진단용 이미지: 원본 파생 자료, 15의 삭제 대상 포함

근거: OWASP Logging — https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html, OpenTelemetry traces — https://opentelemetry.io/docs/concepts/signals/traces/

## 피드백 역추적 — 확정
- 진단 화면: Finding 근거 ID → 집계 구성 사건·판정·관계 + 원본 시각 조회
- 구분: 틀린 문장 / 틀린 입력 관측
- 원본 만료 시: 수치·참조 정합성 검사 가능, 영상 판정 재검증 불가 표시
- 화면 배치: 미정. 권한·로그 규칙 유지
