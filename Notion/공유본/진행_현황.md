## 2. 한 일

- 서버·웹 화면: 화면 React(첫 클라이언트), 서버 Python, 영상 처리는 별도 워커. 데이터 구조를 서버 한 곳에서 정의해 JSON Schema·API 명세·화면 타입 생성
- 결과 표시: 집계의 분모·판단 불가·제외 표시, 보류된 주장은 사유와 함께 표시. 문장은 서버가 템플릿으로 생성
- 장면 복기: 근거 구간 재생, 프레임 단위 이동, 관절 오버레이, 타임라인을 같은 시간 기준으로 표시. 표시 불가 프레임은 정지 프레임으로 전환
- 영상 준비: 분할·재개 업로드, 내용 검증, 재생용 사본, 프레임 시각 표. 가변 프레임률·회전 처리. 규격 미만은 거절하지 않고 충족 여부 표시
- 선수 지정: 후보 프레임에서 사용자가 두 선수의 트랙을 직접 선택. 한 선수에 여러 트랙 연결 가능, 모순된 선택은 거절, 이력 저장
- 정정·삭제·계정: 본인 지정 정정(이전 결과 보존), 오류 신고, 삭제, 7일 보관 만료, 초대 계정, 관리자 초대·차단
- 실제 영상 시험: 공개 스파링 영상 4개와 변환 영상(세로 회전, HEVC, 가변 프레임률, 10분, 59분 50초, 손상 파일)으로 올리기부터 재생까지 확인. 미지원 형식은 사유와 함께 거절
- 실제 브라우저 점검: 올리기·가져오기·선수 지정·정정·삭제·로그인·초대·차단 확인, 문제 3개 수정(후보 프레임 상자·번호 미표시, 정정 이력 시각 표기, 결과 제목)
- 파이프라인 연동: 좌표, 시간 기준, 역할, 관절 값, 필드 이름 일치. 실제 영상 출력(407프레임, 트랙 9개)의 후보 트랙 진단 값이 파이프라인 진단 파일과 일치
- MMA 그라운드: 사건 4종(테이크다운, 상하 관계, 탑 컨트롤, 서브미션 종료)을 시작·끝 시각, 사건 상태(VALID·UNKNOWN), 결과 필드와 함께 담는 구조, 계약 형식 변환과 시험, 화면 표시
- 없는 것: 지정한 선수를 분석 단계에 연결, 분석 실행 요청, 실제 포즈 모델, 선수 연결·라운드 경계 정정

## 3. 확정된 사항

| 항목 | 내용 |
|---|---|
| 1단계 범위 | 기술 인식, 접촉 여부와 부위 |
| 제품 원칙 | 경기 후 분석, 4종목(복싱·킥복싱·무에타이·MMA), 실사용 코치 검토 불필요, 근거 기반 출력, 반격과 피격 분리, 판단 불가와 없음 구별 |
| 영상 규격 | 720p·30fps 이상 기본, 1080p·60fps 권장. 규격 미만도 거절하지 않고 충족 여부 표시 |
| 시간 기준 | 원본 영상의 프레임 표시 시각(PTS). 프레임 번호와 fps로 시각을 만들지 않음 |
| 관절 값 | 핵심 13개 관절의 (x, y, confidence). z 미사용 |
| 파일 연결 | 파이프라인이 표준 JSON·JSONL 생성, 서버가 가져옴. 기준 이름 `bbox_xyxy`, `score`, `tracking_score`, `timestamp_us`. 현재 실험용 이름(`bbox`, `confidence`)도 수용 |
| 검출 모델 | RT-DETR R18은 프로토타입 기준 모델. 제품 모델은 검토 후 결정 |
| 모델 조건 | 제품용은 상업 이용 가능한 코드·가중치·학습 자료만 사용. YOLO·Ultralytics 계열 사용 안 함 |
| 데이터 보관 | 원본 단기, 결과 장기 보관. 초기에는 초대 운영 |
| 학습 동의 | 학습·평가 이용 동의는 서비스 이용의 필수 조건. 적법성은 법률 검토 필요 |
