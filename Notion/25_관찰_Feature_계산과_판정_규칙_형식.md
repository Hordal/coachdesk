# 25 관찰 Feature 계산과 판정 규칙 형식
상태: 계산 정의·규칙 형식 기본안. 임계값: 02B 3.1·3.2의 임시값(`team-provisional-v1`)을 4-2절에 기입, 확정은 도메인 기준(D01~D04).

## 1. 목적

'분석 항목 및 판정 구조'의 관찰 Feature를 포즈에서 계산하는 방법 + 상태 판정 기준을 코드가 아닌 설정으로 넣는 형식 결정. Feature 계산·판정 엔진: 도메인 기준 없이 구현 가능. 계산한 Feature 분포: 기준 결정에 사용.

## 2. 공통 전처리

| 항목 | 기본안 |
|---|---|
| 입력 | 공통 키포인트 형식의 선수별 시계열(14). 화면 좌표 px, 관절별 상태·confidence |
| 유효 관절 | 점수·가시성 기준 초과 관절만 사용. 기준: 모델별 개발 검증 자료로 결정 |
| 몸 기준 좌표 | 원점 = 골반 중심, 크기 = 몸통 길이(어깨 중심–골반 중심), x축 = 상대 골반 방향 |
| 앞/뒤 매핑 | 스탠스로 왼쪽/오른쪽 → 앞/뒤 변환. 스탠스 판단 불가 → 앞/뒤 의존 Feature도 결측 |
| 평활화 | 원본 값과 별도 사본 저장. 속도·가속도: 평활화 사본에서 계산, 최댓값 손실 검사 |
| 결측 | null + 사유. 0·직전 값으로 채우기 금지 |

- 몸통 길이 정규화: 화면 속 선수 크기 차이 완화용, 실제 길이 아님
- 실제 단위 필요 Feature(거리 상태): 03·T02 보정을 거친 값만 사용

## 3. Feature 계산 정의

'좌표' 열이 2D인 Feature: 카메라 시점에 따라 값 변동. 같은 기준을 다른 시점 영상에 적용 가능한지 별도 검증.

| 분류 | Feature | 계산 | 좌표 | 필요 관절 | 결측 조건 |
|---|---|---|---|---|---|
| 가드 | 손 높이(앞/뒤) | (손목 y − 코 y) / 몸통 길이. 화면 y는 아래로 증가: 코 아래로 내려갈수록 큼 | 2D 정규화 | 코, 손목, 어깨, 골반 | 손목·코 무효 |
| 가드 | 손–턱 거리(앞/뒤) | 손목과 턱 추정점(코와 어깨 중심 사이) 거리 / 몸통 길이 | 2D 정규화 | 코, 손목, 어깨 | 손목 무효 |
| 가드 | 팔꿈치 각도(앞/뒤) | 어깨–팔꿈치–손목 각도 | 2D 각도 | 어깨, 팔꿈치, 손목 | 셋 중 하나 무효 |
| 가드 | 손 전방 거리(앞/뒤) | 손목의 몸 기준 x / 몸통 길이 | 2D 정규화 | 손목, 골반, 상대 골반 | 상대 방향 불명 |
| 스탠스 | 발 간격 | 양 발목 거리 / 몸통 길이 | 2D 정규화 | 발목 | 발목 무효 |
| 스탠스 | 앞발 | 상대 방향으로 더 나간 발 | 2D | 발목, 상대 골반 | 차이가 작으면 판단 불가 |
| 스탠스 | 발 방향 | 뒤꿈치→발끝 벡터와 상대 방향의 각도 | 2D 각도 | 뒤꿈치, 발끝 | 발 점 없는 모델이면 계산 불가 |
| 스탠스 | 골반·어깨 방향 | 좌우 골반(어깨) 벡터 각도 + 화면상 폭 / 몸통 길이 | 2D(회전 근사) | 골반, 어깨 | 겹침으로 좌우 혼동 시 |
| 스탠스·밸런스 | 자세 높이 | (발목 평균 y − 골반 중심 y) / 몸통 길이 | 2D 정규화 | 골반, 발목 | 발목 무효 |
| 스탠스·밸런스 | 무릎 각도(앞/뒤) | 골반–무릎–발목 각도 | 2D 각도 | 골반, 무릎, 발목 | 셋 중 하나 무효 |
| 밸런스 | 상체 기울기 | 골반 중심→어깨 중심 벡터와 화면 수직의 각도 | 2D 각도 | 어깨, 골반 | 카메라 기울기 보정 실패 시 표시 |
| 밸런스 | 머리–골반 정렬 | (코 x − 골반 중심 x) / 몸통 길이 | 2D 정규화 | 코, 골반 | 코 무효 |
| 밸런스 | 골반 이동 속도 | 골반 중심 위치의 시간 미분 / 몸통 길이 | 2D 정규화 | 골반 | 카메라 이동 보정 실패 시 |
| 밸런스 | 공격 후 회복 시간 | 행동 종료 후 주요 Feature가 행동 전 기준값 범위로 돌아올 때까지의 시간 | 시간 | 행동 사건 + 위 Feature | '기준값 범위' = 규칙 매개변수(미정) |
| 타격 | 신전 비율 | 어깨–손목(골반–발목) 거리 / 팔(다리) 길이 | 2D 정규화 | 어깨·팔꿈치·손목 등 | 관절 무효 |
| 타격 | 공격 부위 속도·가속도 | 손목·발목·무릎 위치의 미분 / 몸통 길이 | 2D 정규화 | 해당 관절 | 프레임 간격 불규칙 시 실제 시각으로 계산 |
| 거리 | 선수 간 거리 | 03·T02의 보정된 실제 공간 거리 | 실제 단위 | 측정점(D01) | 보정 없음 → 계산 안 함 |

- 발 점(뒤꿈치·발끝): 팀 연구 포즈(MediaPipe 33점)에 `left_heel`·`right_heel`·`left_foot_index`·`right_foot_index`로 있음. 발 방향 Feature 입력으로 사용 가능, 프레임 밖 좌표는 `off_image`로 구별
- 팀 연구 포즈의 `visibility`: 이미지 안에서 보일 가능성, 관절 정확도 아님. 손목·어깨·팔꿈치 유효 판정의 입력으로만 사용(유효 기준: 모델별 개발 검증으로 결정)

## 4. 판정 규칙 형식

- 상태 판정 기준: 설정 파일로 정의 + 버전 부여
- 엔진: 규칙 읽기 → 프레임별 평가 → StateInterval 생성
- 규칙 임계값이 비어 있으면 해당 상태 미판정

```yaml
rule_id: guard.rear_hand.high_guard
version: team-provisional-v1
category: guard_hand            # 상태 분류
label: high_guard                # ‘분석 항목 및 판정 구조’의 라벨 이름
applies_to:
  sport: [boxing, kickboxing, muay_thai]
  body_part: rear_hand
inputs: [hand_height_rear, hand_chin_distance_rear]
conditions:
  all:
    - { feature: hand_height_rear, op: "<=", value: 0.35 }     # 손 높이 = (손목 y − 코 y)/몸통(화면 y 아래로 증가). 02B 3.2 시작값
    - { feature: hand_chin_distance_rear, op: "<=", value: 0.4 }
min_duration_ms: 200             # 이보다 짧은 상태 변화는 무시. 02B 3.2 시작값
hysteresis: { enter_margin: 0, exit_margin: 0.09 }   # 구현은 상태 유지 완화만 사용. 근거: 35의 4-1절
unknown_if:
  - feature_missing: hand_height_rear
  - stance: unknown
source: { decision: D02, card: S-02, status: provisional }
```

| 엔진 동작 | 규칙 |
|---|---|
| 임계값 null | 규칙 비활성. 해당 상태: 판단 불가, reason_code=`rule_unset` |
| 입력 Feature 결측 | 판단 불가, reason_code=`missing_input` |
| 여러 라벨 조건 동시 참 | 같은 분류 안 배타성·우선순위: 규칙 묶음 설정으로 결정(D02~D04). 미결정 시 판단 불가 |
| 짧은 깜빡임 | min_duration_ms, hysteresis로 억제 |
| 출력 | StateInterval에 rule_id·version을 definition_id·version으로 기록(14) |

학습 기반 상태 분류로 전환해도 같은 출력 형식(StateInterval, 판단 불가 사유, 정의 버전) 유지.

### 4-3. 구현 현황

- 구현: `backend/app/domain/states.py`. 33점 포즈 줄 → 손별 가드 Feature(손 높이·손–턱 거리·팔꿈치 각도·손 전방 거리) → 라벨(`high_guard`·`low_guard`·`long_guard`·`other_guard`) → StateInterval
- 입력 단위: `candidate:N`. 선수 신원 미지정
- 관절 유효: visibility ≥ 0.5(임시), `off_image`·`finite` 거부
- 판단 불가 사유: `no_pose`, `torso_invalid`, `missing_input`, `stance_unknown`, `too_short`(min_duration 200ms 미만). 0·직전 값으로 채우지 않음
- `left_hand`·`right_hand`: 항상 생성. `front_hand`·`rear_hand`: 상대 방향(+1/−1)과 앞발 판정이 있을 때만 생성(R5 입력)
- 연결: 가져오기 입력의 `states_from_poses`(`set_id`, `opponent_direction`)로 가져온 포즈에서 상태 구간 생성. 상대 방향 입력이 없으면 `front_hand`·`rear_hand` 미생성 → 가드 복귀 판단 불가(`missing_input`). 판단 불가 구간 사유는 가져오기 메모에 요약
- 시간 오차: 35의 4절(잡음 없음 1프레임 이내, 실측 잡음에서 드물게 200ms 이상)
- 히스테리시스 구현: `hysteresis_margin` 0.09 몸통 길이(손목 잡음 σ 0.046의 2배, 35의 4-1절). 하이가드는 손 높이·손–턱 기준을, 로우가드는 손 높이 기준을 여유만큼 완화해 유지. 판단 불가·관측 간격 초과(400ms)·손 교체 시 이어받지 않음
- 전환 지연(35의 4-2절): 상태에서 나갈 때만 약 0.09 ÷ 손 속도(몸통/초) + 샘플링 간격만큼 늦음. 상태에 들어갈 때는 변화 없음
- 미구현: 스탠스·밸런스 라벨, 기준 범위(자기 기준), 규칙 파일(YAML) 읽기(현재 매개변수는 코드 기본값), 상대 방향 자동 산출
- 실데이터(팀 clip 01): 211줄 중 판정 가능 구간 소수. 분리 구간만 판정되고 나머지는 `missing_input`·`too_short`

## 5. 도메인 기준 없이 할 수 있는 작업

1. 팀 촬영 영상에서 Feature 계산 → 시계열 그래프·분포 작성
2. 팀이 '확실히 하이가드', '확실히 로우가드' 등 분명한 장면 표시 → Feature 분포 차이 확인. 탐색용, 정답 아님, annotation_source=`team_exploration`으로 기록
3. 도메인 기준 결정 시 그래프·장면을 함께 보며 경계값 후보 선택. 결정 값: 규칙 파일의 value·version, source.card(02의 S 번호)로 기록
4. 2D Feature의 촬영 각도별 변동: 같은 장면의 다각도 영상으로 측정
