# 21 접근과 데이터 격리
상태: 초대 시험 참여자 운영은 기획 결정, 보안 기본안

## 접근 구조
- 공개 가입 비활성화, 관리자 초대 계정만 생성
- 인증: 검증된 프레임워크·제공자 구현 사용, 직접 암호화·비밀번호 저장 방식 개발 금지. 인증 제공자: 배포 환경 선택 시 확정

| 역할 | 접근 |
|---|---|
| 참여자 | 본인 영상·실행·결과 조회·정정·삭제 |
| 워커 | 배정된 작업의 입력·출력만 처리 |
| 운영자 | 작업 상태 기본 조회. 영상 열람: 지원 필요 시 별도 승인·감사 기록 |

- 모든 파일·결과·작업 API: 서버가 owner_id·권한 검사. UUID를 안다는 이유로 허용 금지
- 파일: 공개 정적 경로 금지, 인증 프록시 또는 짧은 유효기간 서명 접근. 서명 URL 발급 전 권한 확인, 공유 기본 비활성화
- 세션: TLS, 안전한 쿠키, 만료·로그아웃 폐기. 쿠키 기반 변경 요청: CSRF 보호
- 사용자별 작업·임시 디렉터리 분리, 업로드 이름의 서버 경로 직접 사용 금지

## 검증
- 사용자 A의 ID·URL을 B 계정에서 조회·삭제·재분석 불가 확인
- 초대 만료·계정 차단·로그아웃·삭제 이후 파일 접근 시험

근거: OWASP Authorization — https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html. 개인정보 처리 동의·상대 선수 권리 판단은 인증과 별개.

## 구현 반영
- 자체 구현으로 시작, 인증 서비스 뒤에 배치(외부 제공자 교체 가능)
- `AUTH_MODE`: dev(기본, 고정 계정, 로그인 없음, 개발·시험 전용) / session(초대 계정 + 쿠키 세션). 배포: session + TLS 위 안전한 쿠키
- 공개 가입 없음. 초대로만 계정 생성: 토큰 해시 저장, 기본 72시간, 1회 사용, 폐기 가능. 수락 시 이용 동의 기록
- 비밀번호: argon2-cffi 해시, 길이(10~128자)만 검사
- 세션 토큰: 해시만 저장. 쿠키 HttpOnly·SameSite=Lax, 12시간 만료, 로그아웃 시 서버 폐기
- 쿠키 인증 변경 요청: 세션 결합 CSRF 토큰을 헤더로 전송
- 로그인 제한: 이메일·IP 기준 15분 5회(IP는 20회). 없는 이메일 / 틀린 비밀번호 응답 동일
- 관리자도 타인 영상·결과 열람 불가. 계정 차단 → 열린 세션 즉시 종료
- 감사 기록: 로그인·초대·차단. 비밀번호·토큰·이메일 미기록
- 서명 주소: 서명이 인증 대체. 모든 요청에서 소유자 검사, 타인 영상·결과·작업은 존재 여부 비공개 404
- 남은 일: 비밀번호 재설정, 이용 안내·동의 문구(현재 검토 전 버전)
