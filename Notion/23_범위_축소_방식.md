# 23 범위 축소 방식
상태: 의사결정 절차 기본안, 핵심 요구 변경은 기획 결정

## 우선 검증 순서

- 검증 순서: 31의 1절 기준
- 각 단계 = 위험 확인 순서, 제품 요구 삭제 순서 아님
- 실제 거리·교정 방향 미검증: 관찰·집계 시제품 제작 가능, 최종 요구 충족 선언 금지

## 실패 시 대응
| 실패 | 우선 대응 | 기획 결정이 필요한 변경 |
|---|---|---|
| 자원 부족 | 배치 축소·캐시·동시성 제한 | 영상 길이 제한 |
| 일부 구간 불명확 | 구간 보류·조건과 분석 비율 표시 | 지원 촬영 조건을 더 제한 |
| 발 방향 등 Feature 관측 불가 | 포즈 모델 교체·조합, 촬영 조건 점검 | 해당 Feature를 쓰는 상태 판정 범위 조정 |
| 사건·접촉·반격 인식 미검증 | 실패 사례·관측 조건·정답 기준 점검, 모델/입력 비교 | 지원 사건·촬영 조건 제한 |
| 교정 근거 부족 | 관찰·집계는 유지, 전문가 기준과 예외 사례 확보 | 교정 기능 축소 |
| 실제 거리 미검증 | 보정·참조 자료·방법 추가 시험 | 실제 거리 요구 철회, 추가 장비·촬영 요구 |
| 평가 자료 부족 | 조건별 실패 탐색, 주장 범위 제한 | 지원 조건·주장 범위 축소 |
| 외부 운영 미준비 | 내부 기술 검증 지속 | 외부 시험 공개 보류 |

- 픽셀 거리를 미터 거리 대신 제공하면서 요구 충족 처리 금지
- 기술 변경: 기본안으로 시도 가능. 제품 핵심 가치·범위를 바꾸는 대안: 근거 구비 후 기획 결정으로 이관

## 기록
- 기록 항목: 실패한 가정, 측정 증거, 검토 대안, 영향받는 요구, 결정자, 재검토 시점
- 도메인 문제 회피용 근거 없는 모델 설명 추가 금지

## 도메인 기준 없이 진행할 작업

도메인 판정 기준(30의 D01~D10) 확정 전 진행 가능한 작업·우선순위·진행 현황. 기준 필요 부분: 빈 설정·임시 운영 정의로 두고, 확정 시 해당 값만 채움.

### 원칙

- 판정 기준은 비우고 구조 먼저 구축. 상태 판정 임계값·반복 문제 기준·피드백 문장: 설정으로 분리, 값 없으면 판단 불가·보류 출력
- 팀이 정한 정의: 임시 표시. 라벨·결과에 임시 운영 정의 버전 기록 → 도메인 기준 확정 시 영향 부분만 재검토. 팀 라벨: 도메인 기준 검토 전까지 최종 정답 아님
- 카메라 1대의 한계: 측정·기록. 일부 장면을 여러 각도로 동시 촬영해 단일 시점 판정 오류를 수치로 기록

### 진행 현황

- 2026-10-07 기준 작업 15개: 완료 5, 일부 구현 4, 설계만 완료 4, 미착수 2

- 설계만 완료 중 관찰 Feature 계산·상태 판정 엔진·사건 정리: 가상 관절·가상 사건으로 모델 없이 구현 착수 가능

### 완료 기준

팀 촬영 영상 하나 입력 시 필요한 결과
- 두 선수의 추적·관절, 원본과 시간이 맞는 오버레이
- 공격 기술 사건(임시 정의 기준), 공격별 접촉 여부·부위, 판단 불가 표시
- 상태 Feature 시계열(상태 판정: 기준 입력 전까지 판단 불가)
- '확인된 크로스 N회 중 접촉 확인 M회, 판단 불가 K회' 형태의 관찰·집계 문장 + 근거 장면
- 단일 시점·다각도 비교로 측정한 접촉 판정 오류율

- 반복 문제·교정 피드백: 이 단계 완료 기준 제외
- 현재 구현: 원본과 시간이 맞는 오버레이(가상 관절), 집계·문장 생성(가상 예제·수동 입력). 나머지: 분석 단계 구현 후 충족
