# 프론트엔드

상세 설계 27의 구현 순서 4~6단계: 실행 목록, 결과 요약, 집계 상세, 사건 상세, 장면 복기(영상 재생, 프레임 단위 이동, 관절 오버레이, 타임라인), 영상 올리기와 처리 진행 화면. 가상 예제와 올린 영상을 함께 보여준다.

TypeScript, React 19, Vite, React Router, TanStack Query. 테스트는 Vitest와 Testing Library를 쓴다.

## 실행

Node.js가 PATH에 잡힌 새 터미널에서 이 디렉터리(`frontend`)에 실행한다. 백엔드는 먼저 띄운다(`backend/README.md`).

```bash
npm install
npm run dev
```

영상을 올려 처리하려면 백엔드 API 서버와 함께 워커(`python -m app.jobs.worker`)도 띄워야 한다.

개발 서버는 http://127.0.0.1:5173 이며 `/api` 요청을 `http://127.0.0.1:8000`(백엔드)로 전달한다(`vite.config.ts`).

| 명령 | 내용 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm test` | 화면 테스트 |
| `npm run typecheck` | 타입 검사 |
| `npm run build` | 타입 검사 후 배포용 빌드(`dist/`) |
| `npm run gen:api` | `../backend/schemas/openapi.json`에서 API 타입(`src/api/schema.d.ts`) 생성 |

백엔드 모델이나 API를 바꾸면 백엔드에서 스키마를 다시 내보내고(`scripts/export_schema.py`) 이 디렉터리에서 `npm run gen:api`를 실행한다. 타입이 어긋나면 `npm run typecheck`가 실패한다.

## 구성

| 경로 | 내용 |
|---|---|
| `src/api/` | 생성된 API 타입, 요청 함수(RFC 9457 오류 변환), 조회 훅 |
| `src/components/` | 표시 규칙을 지키는 공통 컴포넌트 |
| `src/features/` | 화면: runs(목록·상위 레이아웃), findings(요약), aggregate-detail, event, scene(장면 복기) |
| `src/player/` | 영상 재생: 프레임 표 계산, 표시 프레임 시각 확인, 이동 후 표시 검증, 정지 프레임, 관절 오버레이 |
| `src/strings/ko.ts` | 한국어 문구와 코드 → 표기 사전. 사전에 없는 코드는 코드 그대로 보여준다 |
| `src/lib/format.ts` | 시각·구간·비율 표시 |
| `src/styles/` | 디자인 토큰(라이트·다크)과 화면 스타일 |
| `tests/` | 서식, 컴포넌트, 화면 테스트 |

## 화면

| 경로 | 화면 |
|---|---|
| `/` | 분석 실행 목록 |
| `/runs/:runId` | 결과 요약: 관찰·집계, 원인 가설, 교정 방향, 근거 장면 |
| `/runs/:runId/aggregates/:aggregateId` | 집계 상세: 분자·분모·판단 불가·제외와 구성 사건 |
| `/runs/:runId/events/:eventId` | 사건 상세: 판정, 관계, 공방, 근거 |
| `/runs/:runId/scene?from_us=&to_us=` | 장면 복기: 근거 구간의 영상, 관절 오버레이, 상태·행동·접촉 타임라인, 판정 |

## 장면 복기의 시간 동기화(상세 설계 05)

| 동작 | 구현 |
|---|---|
| 프레임 시각 | 서버가 ffprobe로 읽은 실제 표시 시각(PTS)의 표를 사용. 명목 fps로 시각을 만들지 않음 |
| 표시된 프레임 확인 | `requestVideoFrameCallback`의 `mediaTime`으로 화면에 표시된 프레임을 확인. 지원하지 않는 브라우저는 재생 위치로 대신하고 그 사실을 표시 |
| 프레임 이동 | 이전·다음 프레임은 표의 이웃 프레임. 목표 프레임과 다음 프레임 사이 중간 지점으로 탐색(`fastSeek` 미사용) |
| 이동 후 검증 | 이동한 뒤 목표 프레임이 실제로 표시되는지 확인. 0.5초 안에 표시되지 않으면 브라우저가 프레임을 건너뛴 것으로 보고 디코더가 식별한 정지 프레임으로 자동 전환하며 안내 |
| 관절 오버레이 | 서버가 표시 좌표로 되돌려 준 관절을 영상과 같은 좌표계(viewBox)로 그림. 좌표가 없는 관절(missing)은 그리지 않음. 프레임의 표시 시각에 맞는 관측만 그리고, 허용 오차 밖이면 비움 |
| 타임라인 | 항목을 누르면 그 사건 구간의 첫 프레임으로 이동. 현재 프레임 위치선 표시 |
| 구간 끝 | 재생이 구간 끝에 닿으면 멈추고 구간의 마지막 프레임으로 되돌림 |
| 한도 | 프레임 표와 관절은 60초 이하 구간에서만 받음. 더 긴 구간은 영상 재생과 타임라인만 제공 |

브라우저는 영상 파일의 프레임 길이 정보 때문에 프레임을 건너뛸 수 있다. 개발용 가변 프레임률 영상(demo-video-02)에서 실제로 확인되었고, 자동 전환이 이를 처리한다.

## 표시 규칙(상세 설계 19)을 지키는 방식

| 규칙 | 구현 |
|---|---|
| 미산출 값을 0으로 표시하지 않음 | `DataValue`: null이면 ‘확인 불가’와 사유. 테스트로 확인 |
| 색만으로 구별하지 않음 | `StatusBadge`: 아이콘과 텍스트를 함께 표시. 패턴(점선·빗금) 병용 |
| 분모·판단 불가·제외를 함께 표시 | `CountBreakdown`: 분모 0이면 ‘비율 없음’. 퍼센트는 만들지 않음 |
| 값이 없는 구간을 0으로 잇지 않음 | `TimelineTrack`: 기록이 없는 구간은 공백, ‘기록된 내용이 없다는 뜻’ 안내 |
| 보류된 주장을 숨기지 않음 | `FindingCard`: 사유와 함께 표시. 교정이 없으면 ‘문제가 없다는 뜻이 아님’ 안내 |
| 원본이 없어도 구조화된 근거 표시 | `EvidenceLink`, `ExpiredNotice`: 구간과 선수는 보이고 재생 불가를 안내 |
| 숫자·문장은 서버에서 생성 | 화면은 서버가 준 문장을 그대로 표시하고 숫자를 만들지 않음 |
| 오류에 내부 정보 노출 금지 | `ProblemNotice`: 안전한 제목과 문의용 확인 번호만 표시 |

## 개발용 영상

장면 복기를 보려면 백엔드에서 시험 영상을 만들어 둔다(`backend/README.md`의 ‘개발용 영상’). 영상이 없으면 장면 복기 화면은 영상 없이 안내와 타임라인만 보여준다.

## 알려진 사항

- TypeScript는 5.x로 고정했다. 7.x는 `openapi-typescript`가 쓰는 컴파일러 API를 제공하지 않아 타입 생성이 실패한다.
- 관절 오버레이는 개발용 가상 관절 데이터로만 확인했다. 실제 포즈 모델의 출력은 구현 순서 10단계에서 연결한다.
- Windows에서 개발 서버가 연속된 파일 수정을 놓치면 이전 모듈이 남을 수 있다. 화면이 비어 있고 콘솔에 정의되지 않은 값 오류가 나오면 `npm run dev -- --force`로 다시 시작한다.

## 영상 올리기

- `/upload`: 파일과 종목을 고르면 `src/upload/engine.ts`가 조각으로 나누어 보낸다. 조각마다 SHA-256을 계산해 보내고, 연결·서버 오류는 간격을 늘려 다시 시도하며, 요청 오류(4xx)는 다시 시도하지 않는다.
- 업로드가 끊기면 같은 파일(이름, 크기, 수정 시각, 종목)을 다시 선택했을 때 서버가 받은 조각을 확인해 나머지만 보낸다. 서버에 업로드가 없으면 새 키로 처음부터 시작한다.
- `/videos/:videoId`: 처리 단계별 진행과 취소, 실패 시 안전한 제목·영상 시각·확인 번호를 보여 준다. 완료 예정 시간은 보여 주지 않는다. 처리 중에는 1.5초마다 다시 읽는다.
- `/videos/:videoId/import`: 사건·판정 JSON 파일을 고르면 서버로 보내 새 실행을 만들고 결과 화면으로 이동한다. 서버의 검증 오류 목록은 그대로 보여 준다.
- `/runs/:runId/corrections`: 본인 지정 정정(선택 → 미리 보기 → 확인), 정정 이력, 오류 신고, 의도 설명. 이미 정정된 결과에는 최신 결과 링크를 보여 주고 정정을 막는다.
- `/videos/:videoId`의 삭제 영역: 원본만 삭제와 결과까지 삭제를 확인 단계를 거쳐 실행하며, 정리가 끝나지 않으면 완료라고 하지 않고 정리 중이라고 안내한다.
- 인증: `/login`, `/invite/:token`(계정 만들기), `/admin`(초대·차단, 관리자만). 로그인이 필요하다는 응답(401)은 로그인 화면으로 보내고 원래 가려던 화면으로 돌아온다. 변경 요청에는 `GET /me`가 준 CSRF 토큰을 헤더로 붙인다. `dev` 모드에서는 로그인 화면이 나오지 않는다.
- `/videos/:videoId/observations`: 선수 검출·추적 결과(`metadata.json`, `tracking_frames.jsonl`, `detection_frames.jsonl`)를 가져오고 후보 트랙의 진단 값을 표로 보여 준다. 트랙은 후보이며 선수가 아니라는 안내가 붙고, 서버의 검증 오류 목록은 그대로 보여 준다.
- 검출·추적 결과 페이지의 선수 지정: 후보 프레임 위에 트랙 상자와 번호를 겹쳐 보여 주고 트랙마다 나·상대·지정 안 함을 고른다. 미리 고르지 않으며 나와 상대가 하나 이상씩 있어야 확정할 수 있고, 나와 상대 바꾸기와 서버 거절 사유 표시가 있다.
- 분석 결과가 없는 실행(분석 전)은 장면 복기 화면에서 영상 전체를 재생한다.
